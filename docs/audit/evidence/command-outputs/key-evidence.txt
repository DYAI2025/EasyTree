    93	## Backend (API + Worker)
    94	
    95	`apps/api` ist **ein** NestJS-Codepaket mit **zwei** Entrypoints (ADR-001 §2):
    96	
    97	- `src/main.ts` — HTTP-API auf `API_PORT` (aus `@easytree/config`), mit `GET /health`
    98	  (Liveness) und `GET /ready` (Readiness, 503 bei nicht bereiten Abhängigkeiten).
    99	- `src/worker.ts` — Hintergrund-Worker via `NestFactory.createApplicationContext`;
   100	  identische Module/DI/Konfiguration, aber **kein** HTTP-Listener und kein Port.
   101	
   102	Querschnitt: `x-correlation-id` wird pro Request übernommen oder als UUID erzeugt und in
   103	der Response gespiegelt; Fehler werden als RFC-7807-artiges JSON (`type`/`title`/`status`/
   104	`detail`/`correlationId`) ohne Stacktraces oder Secretwerte ausgegeben; SIGTERM führt über
   105	`enableShutdownHooks()` zu einem sauberen Shutdown.
   106	
   107	```bash
   108	pnpm --filter @easytree/api test          # Vitest (SWC-Transform für Nest-Decorators)
   109	pnpm --filter @easytree/api build         # tsc → apps/api/dist
   110	node apps/api/dist/main.js                # API starten (Env gemäß .env.example)
   111	node apps/api/dist/worker.js              # Worker starten (öffnet keinen Port)
   112	```
   113	
   114	## Web (PWA-Shell)
   115	
   116	`apps/web` ist die Next.js-Shell (App Router, Next 16, React 19) für easyTree (EYT-41,
   117	ADR-001 §1/§5):
   118	
   119	- **Shell & A11y-Baseline:** semantische Landmarks (`header`/`nav`/`main`/`footer`),
   120	  Skip-Link als erstes fokussierbares Element (Ziel `#hauptinhalt`), sichtbare
   121	  Fokusstile, `html lang="de"`, mobile-first Layout, System-Font-Stack (keine
   122	  Google-Font-Imports — der Build funktioniert offline). Statusanzeigen sind nie nur
   123	  über Farbe kodiert (immer Text + Symbol).
   124	- **PWA:** `app/manifest.ts` liefert `/manifest.webmanifest` (name `easyTree`,
   125	  `display: standalone`, Platzhalter-Icons unter `public/icons/`). Ausdrücklich
   126	  **kein** Service Worker und **keine** Offline-Schreib-/Sync-Queue.
   127	- **API-Zugriff nur über Injektion:** `lib/api-client.ts` (`createApiClient(baseUrl,
   128	fetchImpl)`) + `lib/api-client-provider.tsx` (React-Context). Die einzige
   129	  Konstruktionsstelle ist die Kompositionswurzel `app/providers.tsx`
   130	  (`NEXT_PUBLIC_API_URL`, Default `http://localhost:3001`); Komponenten konstruieren
   131	  nie selbst einen Client, ohne Provider wirft `useApiClient()` einen verständlichen
   132	  Fehler. Ein statischer Guard-Test stellt sicher, dass `apps/web` nirgends das
   133	  Supabase-JS-SDK importiert.
   134	- **UI-Primitives:** `packages/ui` (`@easytree/ui`) liefert domänenfreie Bausteine
   135	  (`Button`, `Card`, `VisuallyHidden`) ohne Fachlogik; das Styling gehört der App
   136	  (`app/globals.css`).
   137	
   138	```bash
   139	pnpm --filter @easytree/web dev     # Dev-Server auf http://localhost:3000
   140	pnpm --filter @easytree/web build   # next build (Turbopack)
   141	pnpm --filter @easytree/web start   # Produktionsserver nach Build
   142	pnpm --filter @easytree/web test    # Vitest: api-client, a11y (axe), Supabase-Guard
   143	pnpm --filter @easytree/ui test     # Vitest: Primitives
   144	```
   145	
   146	Automatisierte A11y-Checks (axe: 0 Violations, Skip-Link erstes Tab-Ziel,
   147	`main`-Landmark, `lang`) laufen in `apps/web/test/a11y.test.tsx`; die **manuelle**
   148	Checkliste (Tastatur, Fokusreihenfolge, 200 %-Zoom, non-color Status, Kontrast,
   149	Screenreader) liegt in
   150	[`docs/runbooks/a11y-checklist.md`](docs/runbooks/a11y-checklist.md) — Status:
   151	manuell noch offen.
   152	
   153	## Datenbank
   154	
   155	Lokaler Supabase-Stack (Postgres 17, Auth, Storage) via Docker; die Supabase CLI ist als
   156	devDependency versioniert (`pnpm exec supabase …`). SQL-Migrationen unter
   157	`supabase/migrations/` sind die **einzige** Schemaquelle — Schemaänderungen über das
   158	Supabase-Dashboard sind verboten. Details, Reset-Workflow und Reviewpflicht:
   159	[`docs/runbooks/database-workflow.md`](docs/runbooks/database-workflow.md).
   160	
   161	```bash
   162	pnpm exec supabase start     # Stack starten (erstmalig: Docker-Images ziehen)
   163	pnpm exec supabase db reset  # DB aus Migrationen + supabase/seed.sql neu aufbauen
   164	pnpm exec supabase test db   # pgTAP-Tests (supabase/tests/*.sql)
   165	pnpm exec supabase stop      # Stack stoppen
   166	```
   167	
   168	Hinweise: pnpm ist der einzige zulässige Paketmanager (keine `package-lock.json`/`yarn.lock`);
   169	Umgebungsdateien (`.env*`) werden nie committet — nur `.env.example` mit Platzhalterwerten.

7:## 1. Produktziel
9:Der Arboscus Teamplaner ist eine mobile-first, installierbare Web-App für die visuelle Planung von Mitarbeitern, Baustellen, Tätigkeiten, Fähigkeiten, Abwesenheiten, Geräten, Fahrzeugen, Zustandsmeldungen und persönlichen Arbeitszeiten.
15:Die Wochenansicht ist die wichtigste operative Ansicht. Ergänzend bestehen Monatsansicht und rollierende Vier-Wochen-Planung.
17:## 2. Rollen
19:### Mitarbeiter
22:- sieht Teammitglieder nur für gemeinsamen Ort und Zeitraum;
23:- bestätigt eine veröffentlichte Woche oder lehnt einen Termin begründet ab;
24:- erfasst Abwesenheiten, Arbeitszeit und Zustandsmeldungen;
27:### Administrator
29:- verwaltet Benutzer, Mitarbeiter, Rollen, atomare Berechtigungen und Stammdaten;
34:### Geschäftsführung
39:Jeder Benutzer besitzt genau eine Rolle. Rechte werden serverseitig geprüft und können später granular angepasst werden.
41:## 3. Kern-MVP
45:- Rollen und atomare Berechtigungen;
46:- Wochen-, Monats- und Vier-Wochen-Planung;
50:- Entwurf, Veröffentlichung und Planversionen;
51:- Konfliktprüfung für Doppelbelegung, genehmigte Abwesenheit, aktivierte Kapazität und exklusive Ressourcen;
52:- Wochenbestätigung und terminbezogene Neubestätigung bei wesentlichen Änderungen;
53:- Ablehnung mit Kategorie und Pflichttext;
54:- In-App- und E-Mail-Benachrichtigung;
56:- Urlaub, Krankheit und weitere Abwesenheiten;
58:- eindeutige Geräte und Fahrzeuge, Reservierung, Verfügbarkeit und Zustandsmeldung;
61:- Zeitfreigabe und begründete administrative Korrektur unter Erhalt des Originals;
63:- baustellenbezogenes Wetter für heute und morgen.
65:## 4. Wetter
67:Wetter wird aus der sichtbaren Baustellenzuweisung abgeleitet. Es erfolgt kein Mitarbeitertracking, kein Geofencing und keine Hintergrundortung.
71:- Wetterzustand;

94:- Prognose und Ozon über einen austauschbaren Wetteradapter;
99:## 5. Erweiterter Bestandteil des ersten Releases

112:## 6. Post-MVP: Planungsökonomie und Maschinenverleih
114:Das Modul wird dokumentiert und in Jira vorbereitet, ist aber weder Teil der MVP-Implementierung noch der MVP-Abnahme.
121:- individuelle Netto-Stunden- oder Tagessätze je Mitarbeiter, freiem Mitarbeiter, Gerät, Maschine oder Fahrzeug;
122:- keine Standardsätze nach Rolle oder Ressourcentyp;
129:- Auswertung nach Einsatz, Baustelle, Tag, Woche und freiem Zeitraum.

137:- Supabase Auth als bevorzugte Authentifizierung;
145:## 8. Datenschutz und Sicherheit

156:## 9. Umsetzungsphasen
164:7. separat freizugebendes Post-MVP-Modul Planungsökonomie/Maschinenverleih
166:## 10. MVP-Abnahme
168:Der MVP ist fachlich abnahmefähig, wenn unter anderem:
171:- unzulässige Doppelbelegungen und genehmigte Abwesenheiten Veröffentlichung blockieren;
173:- relevante Baustelleninformationen, Ressourcen und Wetter verfügbar sind;
